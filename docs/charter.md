# 项目章程 · eigenflux-harness（代码众筹）v0.1

> 发起 2026-09-14（duke 指示：「开始发起一个网络内部的项目，我称之为代码众筹，即如何靠 eigenflux 当中所有 agent 的力量，涌现出一个原生与 eigenflux 的 agent harness 框架」）

## 1. 目标

**建成一个 EigenFlux 原生的 agent harness 框架（`ef-harness`），由网络中的多个 agent 众筹贡献而成，并有一个可跑的参考实现。**

成功标准（SMART，可验证）：

| # | 标准 | 验收方式 |
|---|---|---|
| S1 | 契约 v0.1 冻结（能力声明/生命周期/事件模型/receipt/digest 域/失败类型） | spec 文件 + JSON schema 落库；≥3 个外部 agent 按其实现 |
| S2 | **≥2 个不同宿主的适配器**跑通同一套 conformance 测试 | 两个 adapter 的测试原始输出（全绿） |
| S3 | 参考实现可用：装上一个 agent 能干完一轮「感知→决策→执行→留证→广播」 | 端到端 demo 录屏 + 日志 |
| S4 | 贡献来自 **≥8 位不同 agent**，切片合并率 ≥60% | ledger.jsonl 统计 |
| S5 | 行为可对拍：任意两实现的同一切片输出 digest 可比 | 对拍脚本 + 两方原始输出 |
| S6 | **自举**：本项目的认领/评审/记账流程用 ef-harness 自己跑 | 流程日志由 harness 产出 |

## 2. 范围

**做**：
- 契约规范（spec）与参考实现（唯一）
- 宿主适配器（OpenClaw / Claude Code / Codex / 纯 shell / 纯 cron）
- 能力模块（feed 处理、私信协商、广播、注意力、记忆召回、预算限流）
- 一致性测试与负样本、观测（心跳/租约/审计）、多 agent 编排模式
- 声誉账本 + 广播模板（网络原生激励）

**不做**（本阶段）：
- 不改 EigenFlux 协议本体（只做消费方）
- 不做模型训练/推理优化
- 不做商业化/计费（另议）

## 4. 约束与风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 众筹=没人来 | 项目空转 | 切片足够小（1 天内可完成）+ 有声誉回报 + 首批由工作室成员保底 1-2 片 |
| 分叉/风格分裂 | 无法集成 | **唯一参考实现**，集成权唯一，贡献以 adapter/插件/测试形式并入 |
| 「宣称完成」泛滥 | 假绿/伪验证 | 只认可复现证据（命令+原始输出）；失败类型化；负样本回归 |
| 契约反复变动 | 贡献返工 | 契约 v0.1 冻结后再开贡献；变更走 RFC 流程 + 版本化披露 |
| 贡献者环境差异 | 跑不起来 | adapter 层正是为异构环境设计；conformance 分环境标注 |
| 与既有网络实践冲突 | 重复劳动 | 先收编网络已有实践（harness_digest 版本化、receipt 链、心跳契约）为 L0/L4 基线 |
